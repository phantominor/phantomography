# /relink：全站連結整合

不預先留指向還沒建立的頁面的連結。等新頁面寫好後，定期把全站讀過一次，依實際內容補連結。

## 什麼時候跑

使用者說 `/relink` 時直接跑。遇到下列時機，Claude 主動**問使用者要不要跑一次**，使用者同意才跑：

- 完成一定份量的內容：一個分類寫完（例如病患主訴 17 頁寫完）、基礎醫學某一科寫完。
- 要開始新的結構內容：開始寫另一個分類（例如主訴寫完、要開始檢查檢驗或基礎醫學）之前。
- 逐篇筆記累積到一定數量：上次 relink 之後新增約 10 篇。

上次 relink 的日期看 `UPDATE.md` 的「全站連結整合」紀錄；從沒跑過的話以 2026/10/26 為起點。使用者說先不要時，在「還沒做」清單留著，到下一個時機再問。

## 步驟

### 1. 列出連結目標

- 所有頁面的 `title`、`aliases` 與 h2/h3 標題（`frontend/content/**/*.md`，含 `content/journal/`；`_charts/` 除外）。
- 看 `UPDATE.md` 找上次 relink 的日期，列出那之後新增或大改的頁面，這些是這次的重點目標。

### 2. 逐頁讀完並補連結

每一頁都要**整頁讀過**，不只用 grep 找詞。頁數多時一次處理一個分類，分次跑完，進度記在對話裡。

要補的連結有兩種：

1. **詞彙提及**：提到某個疾病、機轉、檢查、藥物，而別頁有專門的段落，但這裡還沒連過去的，在首次出現的地方加 `[[頁面#標題|顯示文字]]`（沿用既有慣例：每頁首次出現才連，長頁可以每個 h2 首次出現連一次）。
2. **主題相關**：沒有直接提到詞彙，但別頁有值得延伸閱讀的獨立討論（例如臨床頁的病生理對應到基礎醫學的機轉、某個主題在逐篇筆記有完整討論），就在相關段落末尾加一行：
   ```markdown
   - 詳見 [[頁面#標題|顯示文字]]
   - 詳見 [[20261022-community-hiv|社區醫學：愛滋篩檢、預防與感染者就醫]]（逐篇筆記）
   ```

要補的方向：

- 臨床醫學 ↔ 基礎醫學（雙向：臨床連到機轉，基礎連回臨床意義）。
- 臨床各分類之間（病患主訴、諸病微精、檢查檢驗、治療處置……）。
- 知識頁 → 逐篇筆記：太瑣碎、沒有整合進知識頁的內容，從相關段落用「詳見」連出去。逐篇筆記 → 知識頁也順便檢查。

原則：

- 只動連結，不改內容。發現內容錯誤、矛盾或缺漏時，記下來回報，不順手修改。
- 連結要指到最精確的段落（`#標題`），不要只連到頁面。
- 寧缺勿濫：只連真的有幫助的地方，同一段不要堆一串連結。
- 流程圖（```mermaid、`_charts/`）裡不加連結。

### 3. 收尾

1. 跑 `cd frontend && npm run build`，確認沒有新的失效連結。
2. 回報：每頁補了幾個連結、比較重要的新連結、發現的內容問題。
3. 記進 `UPDATE.md`（標題寫「全站連結整合」，註明這次掃描的範圍，下次以這個日期為準）、commit（不 push）。
