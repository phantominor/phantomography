# 醫學周報藍圖 v4

整合 v1–v3 與第 43、44 週兩輪評分的結果，是目前完整的周報規格。v1 的檔案位置、frontmatter、期別計算、列表與導覽（§3–§5）不變；其餘以本版為準。

最大的改變：**周報不再經過使用者審核**。Claude 依本版規則直接寫成正式檔、建置檢查、commit，回報後使用者想改再提；使用者的意見累積成新版藍圖。

## 1. 讀者與定位

- 讀者：台灣的醫學生、PGY、住院醫師。
- 定位：正式的醫學周報，讓讀者掌握這週醫界值得知道、聊得起來的事：研究、指引、新藥、政策，也包括醫界人物、刑案、醫師過勞等事件。
- 寫法：像「把關鍵字丟給搜尋引擎或直接問人，請對方整理這則新聞」那樣的介紹說明文，讀者不用先懂背景也能進入狀況。

## 2. 份量與分段

- 每期 **10–14 則**，約 20 分鐘讀完；各分段不限一則，有好題材就多收。
- 話題類（醫界人物事件、刑案、醫師過勞、醫院爭議）每週最多 5 則，而且要收：性騷擾刑案、醫師猝逝這類住院醫師會拿來聊的事件不要因為敏感就略過。
- 寧可少而深：不寫兩三句的短訊；讀不到原文、寫不出背景的題材不收。
- h2 分段固定順序（`lib/weekly.js` 的 `WEEKLY_KINDS`），沒有內容的整段不寫：本週頭條、臨床更新、新研究、台灣醫界、國際醫界、正反觀點、醫學史與冷知識、本週數字、論壇熱議（未查證）。
- 論壇只收能寫出評析的；網友討論也可以併進相關新聞那則的「網友怎麼看」小節。

## 3. 每則條目

```markdown
### 新聞標題式：主詞 + 發生了什麼

::::news{subjects="…" evidence="…" source="…" date="…" url="…"}
導言：一段話交代誰、何時、做了什麼、為什麼重要，關鍵處粗體。

:::background
- **專有名詞或疾病**：一兩句說明，連到知識頁。
- **標準做法或現況**：這則新聞要改變的是什麼。
- **導火線、時空背景**：事情為什麼在這時候發生。
:::

#### 小標（例如試驗怎麼做、結果、怎麼解讀、事件經過、雙方觀點、台灣現況）

敘述段落或條列；數字多的用表格；機轉配圖。

出處：[來源一](…)、[來源二](…)
::::
```

- **背景知識**：涉及專科知識、政策、疫情的一律要有，放在導言之後；內容包括醫學知識，也包括導火線、時空背景、相關情勢。單純事件可以省略。
- **標題**：新聞標題式，一眼看懂；不用小說式、純數字或吐槽式標題。
- **語調**：正式、敘述性的專業說明文，像有人當面講解；不口語（「尚未確定的事」而不是「還不能說的事」、「未接種疫苗」而不是「沒打疫苗」，標題尤其注意）；不要「可以聊什麼」這類欄位，也不要「八卦看完」這種口語轉折。
- **順序**：依邏輯或時間順序，不倒敘。
- **縮寫**：第一次出現寫英文全名與中文，例如「錯配修復缺陷（mismatch repair-deficient，dMMR）」。
- **商品名**：中文商品名後附英文商品名，例如喜克潰（Cytotec）。
- **畫重點**：關鍵數字、結論、清單裡的關鍵詞用粗體；紅字只標極少數必記數字。
- **表格**：法規沿革、多個試驗或規定的比較、國外與台灣的比較、多組數字。
- **圖**：講到致病機轉或藥物作用位置一定配圖；先找開放授權的論文圖（PubMed Central 開放取用論文的原圖從 `pmc-oa-opendata.s3.amazonaws.com` 下載，授權在同目錄的 JSON），找不到再用 mermaid 自己畫。
- **連結**：疾病、藥物、檢查第一次出現就連到知識頁，連得到才連；前幾期報導過的事件連回該期那則。
- **出處**：每則最後一行列出所有讀過的來源；內文不交代推噓數這類來源細節。
- **評析**：論壇與正反觀點可以加「評析」，對各方論點說明同意或反駁的理由；是作者觀點，不寫成事實，不引用沒讀過的研究。

## 4. 內容要查到什麼程度

- **讀者會追問的細節先查好**：試驗是誰做的（藥廠、主持人或單位、刊在哪裡）與結果；病例最後用什麼藥、結果如何；讀得到全文就讀全文。
- **台灣現況必查**：新藥、新適應症、新政策都查台灣的許可證、適應症與健保給付，寫成肯定句（例如「第一線維持治療不在台灣核准的適應症內」）。查法：
    - 許可證與適應症：食藥署藥品許可證開放資料（`https://data.fda.gov.tw/opendata/exportDataList.do?method=ExportData&InfoId=36&logType=3`，zip 內是 JSON，用成分英文名搜尋）。
    - 健保收載與支付價：健保用藥品項開放資料（`https://info.nhi.gov.tw/api/iode0000s01/Dataset?rId=A21030000I-E41001-001`，CSV）；給付條件看該列「給付規定章節連結」的 PDF。
    - 仿單、新聞、醫藥品查驗中心評估報告。
- **縣市層級的規定**：查幾個代表縣市（例如六都）的實際做法寫出來，不寫「需要看各縣市，本期沒有查到」。
- 用盡方法（中英文搜尋、官方資料庫、仿單、新聞）都找不到，才寫查不到。

## 5. 對話

- 每期挑一則用對話寫，寫成 h4 小標（點出場景）接 `:::dialogue` 對話框（每段「**角色**：台詞」，第一個角色靠左；外層 `::::news` 已是四個冒號，對話框用三個）。
- **角色每週換**，不連續兩週用同一組；來源可以是近期的話題人物、真實人物（用化名或諧音）、小說或故事角色、韓劇或醫療劇角色、動漫動畫角色；在背景知識說明角色出處與個性。
- **語氣跟著角色走**：用詞、口頭禪、說話節奏、互動方式都套用角色的性格（嚴厲的教授就簡短犀利、熱血的主角就衝動直率），醫學內容仍要正確、完整；角色的設定與性格要查過來源，不憑印象。
- 已用過的角色：第 43、44 週《外傷重症中心》白江赫與楊載源。
- 提到關鍵試驗時說明是誰做的，再用一問一答帶出結果。
- 結尾不要講完結論就斷掉，用一段符合角色或臨床場景的自然小互動收尾。
- 最適合的題材：觀念轉變、考試答案和臨床做法不同、新藥的機轉。

## 6. 人名與事件

- 報導中已公開的姓名（事件當事人、醫師、死者）可以照寫；刑案被告也照報導寫。
- 偵查中、還沒起訴的人不寫全名；不帶出可識別病人的資訊（病人是新聞主角時不寫名字）。
- 只有單方說法的事件照刊，不必等對方回應；寫進追蹤清單。
- **追蹤清單** `temp/weekly-followups.md`：每期蒐集前先看，清單上的事件有後續（回應、判決、結案、政策定案）就在當期刊出並連回原本那則；本期有尚未結束的事件就寫進清單；追蹤結束就刪掉。
- 舊期數也可以補連後續：後續刊出後，在原本那則最後加一行「後續：…見[[<新期別>#<則標題>|第 N 週周報]]」。

## 7. 來源與合規

- 每一則都要實際讀過原始來源；數字照原文；只讀到摘要時寫「依摘要」。
- 期刊用 RSS 與 PubMed E-utilities，不開文章頁、不偽裝瀏覽器、不繞過任何網站的阻擋；robots.txt 禁止的路徑不用。
- 論壇：PTT 八卦板站內搜尋（推文數 ≥ 20、本期範圍內），文章與推文都要讀過；Dcard 擋程式存取、A-Pen 條款禁止爬蟲與未經同意轉載，都不抓。
- 不轉貼原文段落。

## 8. 產出流程（不經審核）

1. 算期別（`scripts/weekly-period.mjs`），看追蹤清單。
2. 蒐集、篩選、撰寫，直接寫成正式檔 `content/weekly/<YYYY>/<YYYY>-w<WW>.md`；不放 `:::review`、不放評分欄、不先寫草稿。
3. 逐則對照來源檢查，`npm run build` 看失效連結、清單外的 subjects 與 evidence。
4. 已改變臨床建議、且和既有知識頁相關的消息，直接改知識頁：在相關段落加一句，末尾加「詳見 [[<期別檔名>#<則標題>|醫學周報 YYYY 第 N 週]]」；和知識頁現有內容衝突時，保留原內容、加註新證據。
5. 更新追蹤清單、記 `UPDATE.md`、commit（不 push），回報各分段則數、頭條、改了哪些知識頁、新增的追蹤事件。
6. 使用者讀完想改哪裡就直接說；改完更新周報，評語累積到有實質變化時出新版藍圖。
