# 醫學周報藍圖 v2

v1（`weekly_v1.md`）的定位是醫學新聞摘要；第一期審閱後改成「談資」週報：讓醫學生、住院醫師每週花 5–10 分鐘，掌握這週醫界值得聊、聊得起來的話題。除了研究、指引、藥物、政策，也收醫界人物與事件，但守住可信度與分寸。v1 的檔案位置、frontmatter、期別計算、列表與導覽不變，以下只寫有改的部分。

## 1. 讀者與原則

- 讀者：台灣的醫學生、PGY、住院醫師；閱讀情境是零碎時間、值班空檔、聚會前補話題。
- 每則都要讀過原始來源才寫，數字照原文；只讀到摘要時內文寫「依摘要」。
- 人物與事件只收已有正式媒體報導或官方公告的；涉及具名人物、爭議、醫糾的條目，草稿階段包 `:::review`。
- 審核比照逐篇筆記的提案：整期先寫成草稿 `temp/proposals/weekly-<期別>.md`，使用者直接在檔案裡改與回覆，確認後才移到 `content/weekly/` 上線（雲端排程時推分支開 PR）。
- 不帶出可識別病人的資訊；刑案被告不寫全名。
- 預印本與初步研究明確標示，不寫成「重大突破」。

## 2. 每期結構

h2 固定順序，沒有內容的分段整段不寫（清單在 `lib/weekly.js` 的 `WEEKLY_KINDS`）：

| 分段 | 收什麼 |
|---|---|
| 本週頭條 | 這週最值得聊的一件事，可以寫長一點 |
| 臨床更新 | 指引更新、新藥核准、給付與用藥規定；附「對值班的影響」 |
| 新研究 | 3–5 篇重要試驗與研究 |
| 台灣醫界 | 政策、健保、人事、醫院新聞、國內疫情 |
| 國際醫界 | 人物、獎項、爭議事件、國際疫情與衛生 |
| 正反觀點 | 一個有正反方的話題，列雙方論點與台灣的對照 |
| 醫學史與冷知識 | 週年紀念、冷知識 |
| 本週數字 | 一個有衝擊力的統計 |
| 論壇熱議（未查證） | PTT 推文數高的醫療話題，見 §5 |

- v1 的「病例與專題」拿掉；教學型內容改寫進逐篇筆記或知識頁。
- 每期約 5–10 分鐘讀完：本週頭條 1 則、其餘分段各 1–5 則。

## 3. 每則條目

```markdown
### 標題講清楚發生了什麼

:::news{subjects="科別,…" evidence="大型臨床試驗" source="NEJM" date="2026-10-24" url="https://doi.org/…"}
- **重點**：一句話。
- **可以聊什麼**：話題切入點（為什麼值得聊、跟讀者的日常有什麼關係）。
- 細節 1–4 條。
:::
```

- 臨床更新的第二條改成 **對值班的影響**。
- `evidence` 只能用 `EVIDENCE_LEVELS`（`lib/weekly.js`）：大型臨床試驗、初步研究、預印本、指引、專家意見或個案、官方公告、媒體報導、未查證；清單外的建置時警告。渲染成出處列最前面的標籤，預印本與未查證用紅框。
- `subjects` 可以留空（醫學史、論壇），有寫就只能用科別清單。
- `:::news` 裡面還要放 `:::review`、`:::verify` 時，外層用 `::::news`。
- `:::review`：渲染成紅色虛線框「待審核」，建置時列出還有幾則；使用者確認後整個區塊刪掉，不上線。

## 4. 來源

- 期刊：RSS（NEJM、Lancet、JAMA、BMJ、Nature Medicine）與 PubMed E-utilities 讀摘要，`url` 用 doi.org。
- 預印本：medRxiv（evidence 標「預印本」）。
- 藥物法規：FDA、EMA、食藥署公告。
- 台灣：衛福部、疾管署、健保署新聞稿；醫學中心新聞稿；中央社、聯合報、ETtoday 等媒體報導。
- 國際醫界：STAT News、Retraction Watch、Science 新聞版等。
- 獎項：諾貝爾（10 月初）、Lasker（9 月）、唐獎（6 月）依時程排入。
- 不偽裝瀏覽器、不繞過任何網站的阻擋；robots.txt 禁止的路徑（例如 Google News RSS）不用。

## 5. 論壇熱議

- 來源：PTT 八卦板（Gossiping）站內搜尋醫療關鍵字，篩選推文數 ≥ 20、發文日在本期範圍內的文章，依推文數排序取 3–5 則。PTT 的 robots.txt 允許連結加短摘錄的用途，禁止 AI 訓練；每期只讀一次列表與文章。
- Dcard 擋程式存取（網頁與抓取工具都 403），不收；搜尋引擎只找得到舊文、沒有熱度數字。使用者貼連結或內容時可以放。
- A-Pen（醫師認證社群）：服務條款禁止在平台使用網路蜘蛛，平台內容的引用或轉載要事前書面同意，所以不抓、不摘錄；使用者看到的話題，改找公開的新聞或官方來源來寫，不寫成 A-Pen 的內容。若要收 A-Pen 的熱門話題，需先取得營運方醫知彼科技的書面同意。
- 每則寫：標題（附推、噓數）、原文連結與重要回文連結、1–2 句話題摘要（原文在講什麼、推文主要在吵什麼）。摘要要實際讀過推文才寫。
- `evidence="未查證"`；整段開頭放一個 `:::review`，由使用者決定哪些留。
- 不引用個別推文的帳號，不轉貼推文原文。

## 6. 產出流程

- `/weekly` skill：算期別 → 蒐集 → 篩選與分段 → 撰寫草稿到 `temp/proposals/` → 自我檢查（每個數字、說法都對得到來源）→ commit 草稿、回報 → 使用者在草稿裡改完說「周報上線」→ 刪審核標記、移到 `content/weekly/`、套用知識頁修改、build 檢查、commit。
- 和知識頁的整合寫在同一份草稿的最後（「整合到知識頁」），不另開提案檔；插入段落末尾「詳見 [[<期別檔名>#<則標題>|…]]（醫學周報）」。
