# 醫學周報藍圖 v1

本站新增的第四個大分頁「醫學周報」：每週整理上一週各大期刊、指引、官方新聞稿與醫療時事，寫成短摘要並附原文連結，連回醫學筆記。與筆記系統藍圖（`notes-system_v3.md`）並列。

## 1. 定位

- 每週一期，涵蓋上一個完整週（週一到週日，台北時間）。
- 每期約 8–15 則，不固定；沒有值得刊出的內容就少寫，不湊數。
- 多數是短摘要（3–5 行）加原文連結；每期挑 1–3 則深入解讀。
- 和知識頁的關係：
  - 周報內文用 wiki-link 連到知識頁，被連到的段落會自動出現逆連結（`buildBacklinks`），不用手動維護。
  - 已改變臨床建議的消息（新指引、健保給付、核准或下市），比照 `/ingest` 寫整合提案 `temp/proposals/weekly-<期別>.md`，使用者回覆後才改知識頁，插入的段落標註來源（見 §6）。只是研究結果的不改知識頁。

## 2. 每期結構

h2 是性質分段，固定順序；**沒有內容的分段整段不寫**。

| 分段 | 收什麼 |
|---|---|
| 本週焦點 | 1–3 則深入解讀（從下面各類挑出來，不重複列） |
| 新研究 | 重要試驗、統合分析、大型世代研究 |
| 新指引 | 國際與國內學會指引、共識更新 |
| 藥物與器材 | 核准、適應症擴大、安全警訊、下市、回收 |
| 公衛與政策 | 健保給付、國健署、疾管署、WHO 等政策與法規 |
| 疫情 | 國內外疫情、新興傳染病 |
| 時事 | 醫療相關新聞，含醫療糾紛、醫界事件、撤稿與學術不端等負面消息 |
| 新發現 | 基礎研究突破、首例病例 |
| 病例與專題 | 每期 1 個病例分析、1 個疾病專題（見 §4） |

- 分段清單在 `lib/weekly.js` 的 `WEEKLY_KINDS`，要增減先問使用者。
- 每則消息是一個 h3，底下包 `:::news`：

```markdown
### Semaglutide 降低 HFpEF 住院（STEP-HFpEF 後續分析）

:::news{subjects="心臟內科,代謝內分泌科" source="NEJM" date="2026-10-22" url="https://…"}
- 研究設計、對象、主要結果（數字照原文）。
- 對臨床的意義：已改變建議／仍只是研究結果。
- 相關筆記：[[心臟內科#心衰竭|心衰竭]]。
:::
```

  - `subjects`：1–2 個科別，只能用 `data/tags.js` 的科別清單（基礎醫學與諸病微精頁名），清單外的建置時警告。
  - `source`：期刊或機構簡稱；`date`：原文發表日；`url`：原文連結（必填，沒有建置時警告）。
  - 渲染成一列：科別標籤＋「來源 · 日期」連結（`lib/markdown/remarkDirectives.js`）。
- 深入解讀的格式：研究設計 → 主要結果 → 限制 → 對臨床的意義（和既有知識頁、台灣現況的差異），可以用表格與流程圖。

## 3. 檔案與頁面

- 檔案：`content/weekly/<YYYY>/<YYYY>-w<WW>.md`，期別是 ISO 週。

```yaml
---
title: 醫學周報 2026 年第 43 週
issue: 2026-W43
date: 2026-10-27      # 發刊日
start: 2026-10-19     # 涵蓋期間
end: 2026-10-25
---
```

- 期別、期間、檔名、標題都由 `scripts/weekly-period.mjs` 算（固定用台北時間；雲端排程的主機是 UTC），不讓模型自己判斷日期。
- `/weekly` 總覽頁：`::weekly` 列出各期（期間、則數、有哪些分段），上方依科別篩選，`?tag=` 可直接帶入。
- 每期頁首：涵蓋期間、則數、本期出現的科別（點了回到列表篩選）。
- 左側導覽依年份分組，項目是「第 43 週 10/19–10/25」（`lib/weekly.js`），不用改 `nav.js`。
- 搜尋索引的位置標籤是「周報」。

## 4. 來源

- 期刊：NEJM、Lancet 系列、JAMA 系列、BMJ、Nature Medicine、Annals of Internal Medicine 等的線上目錄與 RSS；PubMed 摘要。
- 國際機構：WHO、美國 CDC、FDA、EMA。
- 台灣：衛福部、健保署、疾管署、國健署、食藥署新聞稿；醫藥新聞網站。
- 病例與專題：參考 NEJM 住院醫師電子報的形式（病例分析、單一疾病專題）。病例取材自 NEJM 公開的病例類文章（Case Records、Clinical Problem-Solving、Images in Clinical Medicine）或開放取用的病例報告；疾病專題用多個開放來源寫成，並連到諸病微精。
- 規則：
  - 每一則都要實際讀過來源頁面才寫，不憑記憶；效果量、樣本數、HR 等數字照原文。
  - 付費牆讀不到全文時，以摘要與官方新聞稿為準，並在內文說明「依摘要」。
  - 不轉貼原文段落、不複製圖表，一律自己改寫。
  - 讀不到、無法確認的內容包 `:::verify`。

## 5. 產出流程

- `/weekly` skill（`.claude/skills/weekly/SKILL.md`）：算期別 → 蒐集 → 篩選 → 撰寫 → build 檢查 → 整合提案 → 記 UPDATE.md、commit。
- 自動排程（第二步，repo 推上 GitHub 之後）：用 `/schedule` 建雲端排程，每週一台北時間早上跑 `/weekly`，推到新分支或開 PR，使用者看過合併後才上線。

## 6. 長度與之後可能的調整

- 估計一期 200–400 行（短摘要約 15 則 × 5 行、深入解讀 1–3 則 × 30 行、病例與專題各 40 行），和較長的逐篇筆記差不多；目錄兩層，分段多也找得到。
- 先維持一期一頁。若單期頁面資料超過 Next.js 建議的 128 kB，或使用者覺得太長，再把「病例與專題」拆成獨立的系列。
- 知識頁標註周報來源的方式：v1 先用「詳見 [[<期別檔名>#<則標題>|…]]（醫學周報）」連出去；`:::source` 目前只認逐篇筆記，要不要擴充等第一次整合時再決定。
- 期內依科別篩選單則消息：v1 沒做，之後有需要再加。
