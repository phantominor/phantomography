# phantomography 醫學筆記系統藍圖 v3

2026/10/14 修訂。與 v2 的差異：諸病微精的內容改為直接匯入同學的 TWMLE 筆記（經同意、註明出處），不受段落模板限制、每個次專科一頁不拆分；其他分類可與諸病微精重複、寫得更詳細；清單項目結尾加句號；左右欄貼齊畫面邊緣；釐清「陷阱」與「考點」區塊的分工。

## 1. 定位

- 以醫師國考一階、二階為內容主體的醫學筆記，Markdown 撰寫、渲染成公開的靜態網站（`https://phantomography.vercel.app`），開放搜尋引擎收錄。
- 無登入、無資料庫；所有新增與編輯都在本地與 Claude 協作完成，git 是唯一的版本紀錄。
- 框架：Next.js 15（Pages Router）自建版面，基本使用體驗仿 [hikarimusic/TWMLE](https://hikarimusic.github.io/TWMLE/)（Material for MkDocs）。不採用 MkDocs Material 的原因：2025/11 起進入維護模式，且跨分類連結、來源標註等客製化功能自己掌控比較穩。

## 2. 資訊架構

三大區塊，即上方分頁（只用文字、不放圖示）：首頁、基礎醫學、臨床醫學、逐篇筆記。

- 左側導覽以「導覽區」為單位：基礎醫學、逐篇筆記各一區；臨床醫學的八種切入方式各自獨立成一區，所以諸病微精的頂層（醫學三~六）與基礎醫學的頂層（醫學一~二）位階相同。
- 「臨床醫學」分頁點擊後展開下拉選單（總覽 + 八選一，目前分類打勾）；選定後分頁文字顯示「臨床醫學 / 諸病微精」，不另外增加分頁列。
- 每個導覽區有自己的首頁（`<區>/index.md`）；臨床醫學總覽頁 `/clinical` 列出八種切入方式。
- 導覽結構集中在 `data/nav.js`。

### 2.1 基礎醫學（依國考一階科目）

解剖學（含神經解剖）、組織學、胚胎學、生理學、生物化學（含分子生物、遺傳）、微生物學、免疫學、寄生蟲學、藥理學、病理學、公共衛生。

- 公共衛生另收倫理法規、預防醫學、職業醫學，這些段落標 `:stage[二階]` 徽章（只有徽章，不做一階/二階篩選）。

### 2.2 臨床醫學（八類）

| 分類 | slug | 內容 | 頁面單位 |
|---|---|---|---|
| 諸病微精 | `diseases` | 國考導向的完整地毯式複習內容，匯入 TWMLE（見 2.4） | 國考醫學三~六的分科，每個次專科一頁、不拆分（小兒科上中下合併為一頁） |
| 病患主訴 | `complaints` | 主訴、徵象、異常檢驗值出發的鑑別診斷與 approach | 依器官系統分組 |
| 檢查檢驗 | `tests` | 適應症、判讀、限制、陷阱 | 依檢查類型（血液、心電圖、影像、內視鏡…） |
| 治療處置 | `treatments` | 藥物（依藥理分類）與非藥物（手術、介入、放射、輸血、營養、復健）；左側導覽頂層即「藥物治療」「非藥物治療」兩組 | 依藥理分類/處置類型 |
| 臨床技能 | `skills` | 理學檢查、操作、病史詢問、溝通、病歷書寫、OSCE | 依主題 |
| 臨床通論 | `general` | 跨科原則：輸液電解質、酸鹼、抗生素原則、圍手術期、輸血、疼痛控制… | 依主題 |
| 值班要點 | `oncall` | 實際處理流程：電話問什麼、先開什麼、何時找學長姐/主治、值班紀錄；鑑別診斷一律連回病患主訴 | 依情境 |
| 案例回顧 | `cases` | 去識別化的案例 | 依主題/科別 |

- 家醫科：老年醫學、安寧緩和放諸病微精的家醫科頁；職業醫學放公共衛生（暫定）。
- 諸病微精要完整；其他分類用不同的視角與邏輯結構重新組織同一串知識，**內容與諸病微精重複沒關係**，可以寫得更詳細。各分類之間用連結交織；建置時自動產生段落層級的反向連結（第二期）。

### 2.3 逐篇筆記（journal）

依時間排序的部落格形式，每篇是一次課堂/講座/臨床學習的原始整理，也是知識頁面來源標註的唯一出處。

### 2.4 諸病微精的內容來源：TWMLE

- 來源：同學的筆記網站 [hikarimusic/TWMLE](https://hikarimusic.github.io/TWMLE/)（GitHub `hikarimusic/TWMLE`），作者同意使用，條件是註明出處。
- 2026/10/14 一次匯入醫學三~六共 35 個檔案 → 33 頁。轉換方式：
  - 移除 h1 與 `---` 分隔線；拿掉標題手動編號（改用自動編號）
  - 全形斜線改半形；中文與英文、數字、希臘字母之間補半形空格
  - 清單項目結尾補句號（結尾已是冒號、句號等標點的不補；跨行項目補在最後一行）
- 每頁 frontmatter 加 `credit`（名稱與原頁網址），頁首顯示「內容來源：TWMLE（HikariMusic）」。
- 匯入後由使用者逐章調整、加圖片；之後不再從 TWMLE 重新匯入（避免覆蓋使用者的修改）。
- Claude 先前依段落模板寫的心臟內科初版移到 `trash/cardiology_claude_initial.md` 備查，之後寫其他分類（病患主訴、治療處置等）時可取用。

## 3. 檔案結構與網址

```
/
├── inbox/                             # 使用者丟進來待整理的原始筆記，.gitignore，不進版控
└── frontend/
    ├── content/                       # 所有筆記（Markdown）

    │   ├── clinical/<category>/<page>.md
    │   └── journal/<YYYY>/<YYYYMMDD>-<slug>.md
```

- 網址 = `content/` 底下的相對路徑去掉 `.md`，一律英文 slug；頁面標題用中文（frontmatter `title`）。`index.md` 對應資料夾本身。
- 諸病微精的分科頁不帶醫學三~六前綴（分組只在導覽中呈現），例：`clinical/diseases/cardiology.md` → `/clinical/diseases/cardiology`。完整清單見 `data/nav.js`。

## 4. 內容格式

### 4.1 Frontmatter

知識頁：

```yaml
---
title: 心臟內科
aliases: [Cardiology]
updated: 2026-10-13
status: initial     # Claude 撰寫的初版，頁首顯示「初版，尚待校閱」；使用者校閱後移除
draft: false        # true 的頁面不進正式建置
---
```

逐篇筆記：

```yaml
---
title: 心臟科 Grand Round：Type 2 MI
date: 2026-10-13
type: morning       # lecture | talk | conference | morning | clinical | report | self | discussion
event: 心臟內科 Grand Round
speaker: 王醫師     # 可留空
tags: [心臟內科, ACS]
integrated: true    # 是否已整合進知識頁
linked: []          # 整合到哪些段落，由 Claude 整合時填寫
---
```

type 對照（2026/11/01 改版）：lecture 課程、talk 講座、conference 研討會、morning 晨會、clinical 臨床學習（查房、教學回診）、report 報告（個案報告、journal reading）、self 自主學習（閱讀、自學）、discussion 討論（師生討論、導生會、同儕討論）。

### 4.2 標題層級

| 層級 | 用途 | 自動編號 | 右側目錄 |
|---|---|---|---|
| h1 | 頁名（由 frontmatter `title` 產生，內文不寫） | 無 | 否 |
| h2 | 大類 | 一、二、三 | 是 |
| h3 | 單一疾病/主題 | 1.1、1.2 | 是 |
| h4 | 模板小標 | 無 | 否 |

- 原始檔不寫編號，建置時產生；錨點 id 由標題文字產生（不含編號），插入段落不會讓連結失效。
- 不使用 h5 以下。

### 4.3 段落模板（h4 小標固定順序）

- 疾病：定義 → 流行病學 → 病因與病生理（連到基礎醫學）→ 臨床表現 → 診斷 → 治療（連到治療處置）→ 併發症與預後
- 主訴/徵象/異常值：定義 → Red flags → 鑑別診斷 → 處理流程 → 處置
- 檢查：適應症 → 判讀 → 限制與陷阱
- 藥物：機轉（連到藥理學）→ 適應症 → 用法 → 副作用與禁忌 → 交互作用
- 值班：先問什麼 → 先做什麼 → 何時升級 → 紀錄重點

沒有內容的小標省略，不留空標題。

諸病微精沿用 TWMLE 的結構，不套用這套模板；模板用於 Claude 撰寫的其他分類。

### 4.4 單頁拆分原則

1. 每個次專科（或基礎醫學科目）一頁，不因主題數量拆頁（TWMLE 單頁最多約 70–80 個 h3，右側目錄可捲動）。
2. 單一 h3 細節過多或過於冷門時，細節移到子頁面或 `:::detail`，主頁留摘要與連結。

### 4.5 連結

- Obsidian 相容的 wiki-link：`[[頁面]]`、`[[頁面#標題文字]]`、`[[頁面#標題文字|顯示文字]]`、同頁 `[[#標題文字]]`。
- 「頁面」可以是 slug、中文標題或 aliases 任一。
- 找不到目標時渲染成失效樣式並在建置時警告。

### 4.6 強調（只有兩種）

- **粗體**：一般重點，涵蓋大多數需求。
- 紅字 `:red[文字]`：只給特別重要、難記、關鍵數值、診斷標準切點。重要但人人都記得的不標。一個 h3 段落超過 3 處要檢討（之後由建置檢查警告）。紅字預設不加粗。
- 不用斜體、不用螢光底色、不用其他文字顏色。藍色只屬於連結。

### 4.7 自訂區塊

| 語法 | 名稱 | 圖示（Lucide） | 樣式 |
|---|---|---|---|
| `:::exam` | 考點 | LuTarget | 灰色邊條 |
| `:::mnemonic` | 口訣 | LuLightbulb | 灰色邊條 |
| `:::compare` | 比較 | LuColumns2 | 灰色邊條，內容通常是表格 |
| `:::pitfall` | 陷阱 | LuTriangleAlert | 唯一使用紅色邊條 |
| `:::verify` | 待查證 | LuCircleHelp | 灰色虛線邊條 |
| `:::detail{title="…"}` | 細節（可折疊） | LuChevronRight | 預設收合 |
| `:::source{from="<journal id>"}` | 來源 | LuBookmark | 內容照常顯示，末端一行灰色小字「日期 · 活動 · 講者」連到逐篇筆記 |

「考點」與「陷阱」的分工：

- 考點（`:::exam`）：常考的**知識點**，「要記得什麼」。例：NSTE-ACS 不用血栓溶解劑是常考題。
- 陷阱（`:::pitfall`）：容易**做錯的判斷或處置**，「什麼情況下不要做什麼、做了會怎樣」。必須寫出情境、錯誤做法與後果，例：預激合併心房顫動給房室結阻斷劑 → 衝動全走副傳導路徑 → 可能引發心室顫動。單純「很重要、常考」的內容放考點，不放陷阱。

行內：

- `:stage[二階]`：階段徽章。
- `:q[113-2 醫三 #24]`：考古題出處（語法預留，題庫匯入後啟用）。

### 4.8 其他寫作規範

- 中英文之間加半形空格；數字與單位之間加半形空格（`5 mg/dL`）。
- 中英對照：「急性冠心症（Acute Coronary Syndrome, ACS）」，括號全形；同一對括號不混用全半形。
- 斜線一律半形 `/`。
- 藥名用英文學名小寫；檢驗單位以台灣臨床慣用的傳統單位為主（mg/dL）。
- 清單最多三層。
- 清單項目的描述結尾加句號「。」（結尾是冒號、引出下一層的項目不加）。
- 表格：一般用 GFM；需要合併儲存格時直接寫 HTML `<table>`（`rowspan`/`colspan`）。
- 公式用 KaTeX：`$…$`、`$$…$$`。

## 5. 視覺設計

基本色調與 TWMLE（Material for MkDocs，primary white）一致：黑白灰，簡約精緻。

### 5.1 色彩 tokens

| token | 淺色 | 深色 |
|---|---|---|
| 背景 | `#ffffff` | `#1c1c1e` |
| 次要底色（表頭、區塊） | `#f5f5f5` | `#262628` |
| 內文 | 87% 黑 | 87% 白 |
| 次要文字 | 54% 黑 | 56% 白 |
| 分隔線 | 7% 黑 | 10% 白 |
| 連結 | 靛藍 `#4051b5` | `#8c9eff` |
| 紅字 | `#dc2626` | `#ff5c5c` |

- 深色模式：預設跟隨系統，頂部按鈕可切換並記在 localStorage。
- 整站只有連結藍與強調紅兩種彩色。

### 5.2 字體

- 全站文字（含英文）：霞鶩文楷 TC（LXGW WenKai TC，OFL 授權，Google Fonts），與 TWMLE 相同；載入 400、700 兩種字重。
- 文楷的 700 字重太含蓄，所有粗體（內文粗體、標題、表頭、導覽標題）再加 `-webkit-text-stroke`（token `--bold-stroke`，0.018em）描邊加粗。
- 程式碼：Roboto Mono。

### 5.3 版面

- 頂部列：站名、搜尋（Pagefind，第二期）、深色模式切換、GitHub 連結。
- 上方分頁：純文字。
- 三欄全寬：左側導覽與右側目錄各約 240px，貼齊畫面左右邊緣、只在欄內留邊距（仿 TWMLE）；內文最大約 920px，置中於中間欄。
- 左側導覽：分組標題粗體 + 頁面清單，預設全部展開，分組可收合一層（標題右側箭頭）；目前頁面藍色，尚未建立的頁面灰字。
- 右側目錄：只列 h2、h3；配色同 TWMLE：目前段落藍色、之前的段落灰色、之後的段落黑色。
- 斷點：1220px 以上三欄；960~1220px 左側導覽收進漢堡選單；960px 以下目錄也收進抽屜選單。
- 手機抽屜（仿 Material）：灰底標題列；上方是分頁清單（臨床醫學展開八個分類）；下方是本區導覽，目前頁面那一列右側有「本頁目錄」圖示按鈕，點了切換成目錄面板（左上箭頭返回）。目前頁面不在導覽中時，改在導覽上方顯示一列「本頁目錄」。
- h4 模板小標：一般文字色、略大於內文，不加裝飾。
- 內文 16px、行高 1.8。
- 表格：表頭淺灰底粗體、只有橫線、內容上下左右置中、字級小一號、桌面版不橫向捲動。
- 回到頂部：標題列下方置中的膠囊按鈕（圖示 + 「回到頂部」），往上捲動時才出現（同 TWMLE）。
- 頁尾上一頁/下一頁（依本區導覽順序）。

### 5.4 連結互動

- 同頁錨點（目錄、`[[#標題]]`、標題旁的段落連結）：平滑捲動，目標段落短暫閃一下淡藍底色；尊重「減少動態效果」設定。
- 內文裡的同頁連結跳轉後，左下角出現「返回原處」，點了平滑捲回跳轉前的位置（目錄與段落連結圖示不觸發）；與跨頁的返回按鈕上下疊放。
- 跨頁 wiki-link：不直接跳頁，先開 Notion 式預覽。
  - 桌面版：右側滑出面板（寬約 600px，不遮住主頁面）；點面板外或按 Esc 關閉。
  - 手機版：從下方彈出（高 85vh），有拖曳把手，按住頂端往下拉超過約 100px 即關閉；點遮罩也可關閉。
  - 面板頂端：關閉、頁名、「開啟完整頁面」。預覽內的連結在面板內換內容；連回目前頁面則關閉預覽並捲到該段落。
  - 開啟完整頁面後，左下角出現「返回「原頁名」」膠囊按鈕，點了回到原頁面並還原捲動位置；可按 × 關掉，回到原頁面時自動消失（存在 sessionStorage）。
  - Ctrl/Cmd 點擊照常開新分頁。
  - 內容取自 Next.js 的頁面資料（`/_next/data/<buildId>/<path>.json`），不需要額外產生檔案。
- 頁尾：`Copywrong © 2026 Phantominor · Content licensed under CC BY-NC-SA 4.0`。
- 圖示一律 Lucide（react-icons/lu），不用 emoji。

## 6. 圖片

- 初期放 `public/media/`，用 sharp 腳本轉 WebP、寬度上限 1600px。
- Markdown 只寫邏輯路徑 `media/…`，渲染時加上 `MEDIA_BASE_URL` 前綴；日後搬到 Cloudflare R2 等物件儲存只需上傳並改環境變數。
- 圖說附來源與授權；只放無著作權疑慮的圖。

## 7. 新增筆記流程

1. 使用者把整理好的 Markdown 放進 `inbox/` 或直接貼給 Claude。
2. Claude 存成逐篇筆記（補 frontmatter、去識別化檢查）。
3. Claude 提出整合提案：哪些是新重點（插入哪一頁哪一段）、哪些是細節（開子頁或 `:::detail`）、哪些與既有內容衝突需要使用者決定。
4. 使用者確認後修改，並在逐篇筆記填 `linked`、記錄 `UPDATE.md`。
5. 之後把這套規則寫成 `/ingest` skill。

去識別化：年齡寫區間、不寫日期與醫院、避免罕見特徵組合、不放可辨識影像。
