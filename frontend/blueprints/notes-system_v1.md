# phantomography 醫學筆記系統藍圖 v1

> 已由 [v2](./notes-system_v2.md) 取代。

2026/10/13 與使用者討論定案的第一版。內容涵蓋資訊架構、內容格式、視覺設計、新增流程與分期。

## 1. 定位

- 以醫師國考一階、二階為內容主體的醫學筆記，Markdown 撰寫、渲染成公開的靜態網站（`https://phantomography.vercel.app`），開放搜尋引擎收錄。
- 無登入、無資料庫；所有新增與編輯都在本地與 Claude 協作完成，git 是唯一的版本紀錄。
- 框架：Next.js 15（Pages Router）自建版面，基本使用體驗仿 [hikarimusic/TWMLE](https://hikarimusic.github.io/TWMLE/)（Material for MkDocs）。不採用 MkDocs Material 的原因：2025/11 起進入維護模式，且跨分類連結、來源標註等客製化功能自己掌控比較穩。

## 2. 資訊架構

三大區塊，即上方分頁（只用文字、不放圖示）：首頁、基礎醫學、臨床醫學、逐篇筆記。

### 2.1 基礎醫學（依國考一階科目）

解剖學（含神經解剖）、組織學、胚胎學、生理學、生物化學（含分子生物、遺傳）、微生物學、免疫學、寄生蟲學、藥理學、病理學、公共衛生。

- 公共衛生另收倫理法規、預防醫學、職業醫學，這些段落標 `:stage[二階]` 徽章（只有徽章，不做一階/二階篩選）。

### 2.2 臨床醫學（八類）

| 分類 | slug | 內容 | 頁面單位 |
|---|---|---|---|
| 諸病微精 | `diseases` | 依科別、疾病排序 | 國考醫學三~六的分科，一科一頁（同 TWMLE） |
| 病患主訴 | `complaints` | 主訴、徵象、異常檢驗值出發的鑑別診斷與 approach | 依器官系統分組 |
| 檢查檢驗 | `tests` | 適應症、判讀、限制、陷阱 | 依檢查類型（血液、心電圖、影像、內視鏡…） |
| 治療處置 | `treatments` | 藥物（依藥理分類）與非藥物（手術、介入、放射、輸血、營養、復健）分區顯示 | 依藥理分類/處置類型 |
| 臨床技能 | `skills` | 理學檢查、操作、病史詢問、溝通、病歷書寫、OSCE | 依主題 |
| 臨床通論 | `general` | 跨科原則：輸液電解質、酸鹼、抗生素原則、圍手術期、輸血、疼痛控制… | 依主題 |
| 值班要點 | `oncall` | 實際處理流程：電話問什麼、先開什麼、何時找學長姐/主治、值班紀錄；鑑別診斷一律連回病患主訴 | 依情境 |
| 案例回顧 | `cases` | 去識別化的案例 | 依主題/科別 |

- 家醫科：老年醫學、安寧緩和放諸病微精的家醫科頁；職業醫學放公共衛生（暫定）。
- 各分類之間不重複內容，用連結交織；建置時自動產生段落層級的反向連結。

### 2.3 逐篇筆記（journal）

依時間排序的部落格形式，每篇是一次課堂/講座/臨床學習的原始整理，也是知識頁面來源標註的唯一出處。

## 3. 檔案結構與網址

```
/
├── inbox/                             # 使用者丟進來待整理的原始筆記，.gitignore，不進版控
└── frontend/
    ├── content/                       # 所有筆記（Markdown）
    │   ├── basic/<subject>.md
    │   ├── clinical/<category>/<page>.md
    │   └── journal/<YYYY>/<YYYYMMDD>-<slug>.md
    └── public/media/<分類>/<檔名>.webp # 圖片（初期放 repo）
```

- 網址 = `content/` 底下的相對路徑去掉 `.md`，一律英文 slug；頁面標題用中文（frontmatter `title`）。`index.md` 對應資料夾本身。
- 諸病微精的分科頁不帶醫學三~六前綴（分組只在導覽中呈現），例：`clinical/diseases/cardiology.md` → `/clinical/diseases/cardiology`。完整清單見 `data/nav.js`。

## 4. 內容格式

### 4.1 Frontmatter

知識頁：

```yaml
---
title: 心臟內科
aliases: [Cardiology]
updated: 2026-10-13
draft: false        # true 的頁面不進正式建置
---
```

逐篇筆記：

```yaml
---
title: 心臟科 Grand Round：Type 2 MI
date: 2026-10-13
type: rounds        # lecture | talk | rounds | clinical | case | reading | self
event: 心臟內科 Grand Round
speaker: 王醫師     # 可留空
tags: [心臟內科, ACS]
integrated: true    # 是否已整合進知識頁
linked: []          # 整合到哪些段落，由 Claude 整合時填寫
---
```

type 對照：lecture 課堂、talk 講座/研討會、rounds 晨會/查房/教學迴診、clinical 臨床學習、case 案例討論、reading 閱讀（教科書、指引、期刊）、self 自學整理。

### 4.2 標題層級

| 層級 | 用途 | 自動編號 | 右側目錄 |
|---|---|---|---|
| h1 | 頁名（由 frontmatter `title` 產生，內文不寫） | 無 | 否 |
| h2 | 大類 | 一、二、三 | 是 |
| h3 | 單一疾病/主題 | 1.1、1.2 | 是 |
| h4 | 模板小標 | 無 | 否 |

- 原始檔不寫編號，建置時產生；錨點 id 由標題文字產生（不含編號），插入段落不會讓連結失效。
- 不使用 h5 以下。

### 4.3 段落模板（h4 小標固定順序）

- 疾病：定義 → 流行病學 → 病生理（連到基礎醫學）→ 臨床表現 → 診斷 → 治療（連到治療處置）→ 併發症與預後
- 主訴/徵象/異常值：定義 → Red flags → 鑑別診斷 → 處理流程 → 處置
- 檢查：適應症 → 判讀 → 限制與陷阱
- 藥物：機轉（連到藥理學）→ 適應症 → 用法 → 副作用與禁忌 → 交互作用
- 值班：先問什麼 → 先做什麼 → 何時升級 → 紀錄重點

沒有內容的小標省略，不留空標題。

### 4.4 單頁拆分原則

1. h3 超過約 30 個、或右側目錄超過兩個螢幕高，就沿 h2 邊界拆頁，以內容命名（如「小兒科：新生兒」），不用上/中/下。
2. 單一 h3 細節超過約一個半螢幕、或內容過於冷門，細節移到子頁面，主頁留摘要與連結。
3. 拆頁後由連結檢查抓出失效連結，Claude 全數更新。

### 4.5 連結

- Obsidian 相容的 wiki-link：`[[頁面]]`、`[[頁面#標題文字]]`、`[[頁面#標題文字|顯示文字]]`、同頁 `[[#標題文字]]`。
- 「頁面」可以是 slug、中文標題或 aliases 任一。
- 找不到目標時渲染成失效樣式並在建置時警告。

### 4.6 強調（只有兩種）

- **粗體**：一般重點，涵蓋大多數需求。
- 紅字 `:red[文字]`：只給特別重要、難記、關鍵數值、診斷標準切點。重要但人人都記得的不標。一個 h3 段落超過 3 處要檢討（之後由建置檢查警告）。紅字預設不加粗。
- 不用斜體、不用螢光底色、不用其他文字顏色。藍色只屬於連結。

### 4.7 自訂區塊

| 語法 | 名稱 | 圖示（Lucide） | 樣式 |
|---|---|---|---|
| `:::exam` | 考點 | LuTarget | 灰色邊條 |
| `:::mnemonic` | 口訣 | LuLightbulb | 灰色邊條 |
| `:::compare` | 比較 | LuColumns2 | 灰色邊條，內容通常是表格 |
| `:::pitfall` | 陷阱 | LuTriangleAlert | 唯一使用紅色邊條 |
| `:::verify` | 待查證 | LuCircleHelp | 灰色虛線邊條 |
| `:::detail{title="…"}` | 細節（可折疊） | LuChevronRight | 預設收合 |
| `:::source{from="<journal id>"}` | 來源 | LuBookmark | 內容照常顯示，末端一行灰色小字「日期 · 活動 · 講者」連到逐篇筆記 |

行內：

- `:stage[二階]`：階段徽章。
- `:q[113-2 醫三 #24]`：考古題出處（語法預留，題庫匯入後啟用）。

### 4.8 其他寫作規範

- 中英文之間加半形空格；數字與單位之間加半形空格（`5 mg/dL`）。
- 中英對照：「急性冠心症（Acute Coronary Syndrome, ACS）」，括號全形；同一對括號不混用全半形。
- 斜線一律半形 `/`。
- 藥名用英文學名小寫；檢驗單位以台灣臨床慣用的傳統單位為主（mg/dL）。
- 清單最多三層。
- 表格：一般用 GFM；需要合併儲存格時直接寫 HTML `<table>`（`rowspan`/`colspan`）。
- 公式用 KaTeX：`$…$`、`$$…$$`。

## 5. 視覺設計

基本色調與 TWMLE（Material for MkDocs，primary white）一致：黑白灰，簡約精緻。

### 5.1 色彩 tokens

| token | 淺色 | 深色 |
|---|---|---|
| 背景 | `#ffffff` | `#1c1c1e` |
| 次要底色（表頭、區塊） | `#f5f5f5` | `#262628` |
| 內文 | 87% 黑 | 87% 白 |
| 次要文字 | 54% 黑 | 56% 白 |
| 分隔線 | 7% 黑 | 10% 白 |
| 連結 | 靛藍 `#4051b5` | `#8c9eff` |
| 紅字 | `#c62828` | `#ff6b6b` |

- 深色模式：預設跟隨系統，頂部按鈕可切換並記在 localStorage。
- 整站只有連結藍與強調紅兩種彩色。

### 5.2 字體

- 全站文字：霞鶩文楷 TC（LXGW WenKai TC，OFL 授權，Google Fonts），與 TWMLE 相同；載入 400、700 兩種字重（TWMLE 只載 400，粗體為瀏覽器模擬）。
- 程式碼：Roboto Mono。
- 英文是否改用其他字體，看過樣張後再決定。

### 5.3 版面

- 頂部列：站名、搜尋（Pagefind，第二期）、深色模式切換、GitHub 連結。
- 上方分頁：純文字。
- 三欄：左側導覽約 240px、內文最大約 780px、右側目錄約 220px（只列 h2、h3，隨捲動高亮）。
- 斷點：1220px 以上三欄；960~1220px 左側導覽收進漢堡選單；960px 以下目錄改為文章開頭的可展開區塊。
- 內文 16px、行高 1.8。
- 表格：表頭淺灰底粗體、只有橫線、內容上下左右置中、字級小一號、桌面版不橫向捲動。
- 回到頂部按鈕、頁尾上一頁/下一頁。
- 頁尾：`Copywrong © 2026 Phantominor · Content licensed under CC BY-NC-SA 4.0`。
- 圖示一律 Lucide（react-icons/lu），不用 emoji。

## 6. 圖片

- 初期放 `public/media/`，用 sharp 腳本轉 WebP、寬度上限 1600px。
- Markdown 只寫邏輯路徑 `media/…`，渲染時加上 `MEDIA_BASE_URL` 前綴；日後搬到 Cloudflare R2 等物件儲存只需上傳並改環境變數。
- 圖說附來源與授權；只放無著作權疑慮的圖。

## 7. 新增筆記流程

1. 使用者把整理好的 Markdown 放進 `inbox/` 或直接貼給 Claude。
2. Claude 存成逐篇筆記（補 frontmatter、去識別化檢查）。
3. Claude 提出整合提案：哪些是新重點（插入哪一頁哪一段）、哪些是細節（開子頁或 `:::detail`）、哪些與既有內容衝突需要使用者決定。
4. 使用者確認後修改，並在逐篇筆記填 `linked`、記錄 `UPDATE.md`。
5. 之後把這套規則寫成 `/ingest` skill。

去識別化：年齡寫區間、不寫日期與醫院、避免罕見特徵組合、不放可辨識影像。

## 9. 考古題（第三期）

- 來源：同學製作的免費練習網站 [med-study-rpg](https://med-study-rpg.com/1st)（[二階](https://med-study-rpg.com/2nd)），已授權爬取題目與解析（解析為 AI 生成，可能需要人工修訂）。
- 等筆記結構大致完成後再爬取，控制頻率；存成 `data/exam/` 的結構化資料，再把題目對應到段落，自動計算出題次數，啟用 `:q[…]`。

## 10. 分期

1. 第一期：版面、渲染流程、樣式樣張頁（`/style`）→ 與使用者確認視覺 → 第一個分科頁（心臟內科）跑通完整流程。
2. 第二期：搜尋（Pagefind）、反向連結、建置檢查（失效連結、紅字用量、清單深度）、sitemap/robots、逐篇筆記列表頁、`/ingest` skill、圖片腳本。
3. 第三期：考古題庫、問答卡（標準另訂）、Mermaid 流程圖。
